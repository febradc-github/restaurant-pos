# C-22: Employee Management UI -- Spec

## Acceptance criteria
- [ ] An "Employees" entry appears in `OwnerPage`'s Sider/Menu navigation, without restructuring the existing Table Layout / Menu Management entries.
- [ ] A `Table` lists every employee with their name, role, and active/inactive status.
- [ ] An "Add Employee" `Form` lets the Owner create a new employee; selecting a role reveals the correct credential field (password for Owner/Cashier/Server, 6-digit PIN for Kitchen).
- [ ] The Owner can edit an existing employee's role and reset their credential.
- [ ] The Owner can deactivate and reactivate an employee from this screen; deactivating the Owner's own account or the last active Owner is blocked with a clear, visible error.
- [ ] All actions on this screen call [[US-21]]'s API endpoints; no employee data is read from or written to any other source.

## Out of scope
None -- backend behavior (validation, self-lockout guard) is [[US-21]]'s responsibility; this story only surfaces it correctly.
