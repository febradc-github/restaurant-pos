# C-21: Employee Management API -- Spec

## Acceptance criteria
- [ ] `active` boolean column exists on `users`, default `true`.
- [ ] Owner-gated `POST` endpoint creates an employee with name, role, and the role-appropriate credential (password for Owner/Cashier/Server; unique 6-digit PIN for Kitchen); validation rejects a duplicate email (login roles) or duplicate PIN (Kitchen).
- [ ] Owner-gated `GET` endpoint lists all employees with role and active status.
- [ ] Owner-gated endpoint updates an employee's role and/or resets their credential.
- [ ] Owner-gated endpoints deactivate/reactivate an employee; deactivating/reactivating never touches that user's historical `time_entries` or `orders` rows.
- [ ] Deactivating the caller's own account is rejected with a clear error.
- [ ] Deactivating the last remaining active Owner account is rejected with a clear error.
- [ ] `AuthController::login` rejects a deactivated Cashier/Server/Owner using the same generic-rejection style as an invalid credential.
- [ ] `KitchenClockController::clock` rejects a deactivated Kitchen employee's PIN using the same generic-rejection style as an unrecognized PIN.

## Out of scope
The Owner-facing UI consuming this API -- that's [[US-22]].
