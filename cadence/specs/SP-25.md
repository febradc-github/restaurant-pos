# C-25: Inventory Threshold & Restock API -- Spec

## Acceptance criteria
- [ ] `threshold` column exists on `inventory_items`, defaulting to 0.
- [ ] An endpoint computes a suggested threshold per ingredient from the trailing 30 days of Paid-order consumption (average daily usage), returning 0 for an ingredient with no history in that window.
- [ ] A live endpoint returns, per ingredient, current stock, threshold, and shortfall (quantity needed to reach threshold, 0 if at or above it) -- computed on each request, no stored snapshot or scheduled job.
- [ ] Owner-gated endpoint lets the Owner override an ingredient's threshold directly.
- [ ] All endpoints are Owner-gated (`auth:sanctum` + `role:owner`).
- [ ] Covered by tests including a real mutation/query check of the 30-day windowing (orders inside vs. outside the window) and the no-history-yet zero-threshold case.

## Out of scope
The sales/best-seller endpoints ([[US-24]]) and the dashboard UI consuming this API ([[US-26]]). No scheduled job or stored history table.
