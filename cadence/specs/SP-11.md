# C-11: Server & Cashier Login-Based Time Tracking -- Spec

## Acceptance criteria
- [ ] `time_entries` table/model exists with `user_id`, `role`, `clock_in`, `clock_out` (nullable), `auto_closed` (boolean, default false).
- [ ] `UserRole::Server` accounts can authenticate via the same Sanctum login endpoint Cashier uses today.
- [ ] A Server login creates a `time_entries` row with `clock_in = now()`; a Server logout sets `clock_out = now()` on that user's open row.
- [ ] Cashier's existing login/logout is retrofitted to do the same (create/close a `time_entries` row) without changing Cashier's existing auth behavior or response shape.
- [ ] The Take-Orders frontend page requires login, following the same session-gating pattern already used for Cashier's Checkout page; logging out returns to the login screen.
- [ ] `time_entries` rows are queryable by `user_id` and `role`.

## Out of scope
Date-range filtering and any reporting/dashboard UI over `time_entries` -- belongs to the later analytics epic. Kitchen's PIN-based clock-in ([[US-12]]) and the auto-close job / broader query surface ([[US-13]]) are separate stories.
