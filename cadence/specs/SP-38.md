# C-38: Cashier/Checkout Redesign -- Spec

## Acceptance criteria
- [ ] Each order card shows an order number (`order.id`) and elapsed time since `created_at` (added to the frontend `Order` type)
- [ ] Line items show a right-aligned price; the card has a clear total footer
- [ ] The confirm-payment button's label repeats the order total
- [ ] Orders with more line items than the established threshold (matching today's 12-item worst case) show a truncated list plus a "+N more items" expander instead of growing the card unbounded
- [ ] A shift-summary header shows open order count, pending total, and paid-today
- [ ] A search input filters visible orders by table or item; a sort control (e.g. oldest-first) reorders them
- [ ] "Cancel order" is visually demoted to a quiet/text-style button; the existing Popconfirm confirmation and loading/disabled request state (C-32) are preserved
- [ ] Page remains usable at tablet width (card grid reflows, no horizontal scroll/clipping)
- [ ] New/updated tests cover order identity+elapsed time, truncation/expander, search/sort, and the preserved cancel-confirmation behavior
- [ ] `tsc -b` clean, oxlint clean

## Out of scope
- Backend changes beyond exposing `created_at` on the existing order type (no new endpoints expected; confirm during implementation whether the existing list response is sufficient for the shift-summary numbers)
- Currency symbol/format changes beyond following the codebase's existing convention
