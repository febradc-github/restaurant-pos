# C-37: Owner Console Table Layout Rebuild (Zone Card Grid) -- Design

## Parent
Part of [[EP-35]] -- see [[DS-35]] for the umbrella rationale. Depends on [[US-36]] (dark theme foundation) landing first.

## Problem
`TableLayoutEditor.tsx`'s canvas-based drag/resize floor-plan editor (fixed 800x600, pointer-driven positioning) doesn't match the requested design: a zone-grouped, color-coded card grid with a stat row, inline add-table form, and a detail panel for the selected table. `Table` has no `zone` concept today. Per [[adr-012-redesign-exception-to-adr-011-patch-default]], this story reverses the canvas-keep exception recorded in [[AR-frontend-design-system]].

## Approach
Backend: add a `zone` column to `tables` (migration, nullable/default string), update the Table model, its FormRequest(s), and the TableController's validation/resource output. Frontend: replace `TableLayoutEditor.tsx`'s canvas with a new card-grid component -- stat row (Tables/Seats/Occupied counts), inline "Add table" form (label/shape/capacity/zone), tables rendered as color-coded rounded cards (green=available, red=occupied, orange=reserved) grouped under zone headings, and a right-hand detail panel (selected table's shape/seats/zone/server + Edit/Duplicate/Remove). Table create/edit forms gain a Zone input. `x`/`y`/`width`/`height` positioning fields become vestigial once the canvas is gone -- decide during implementation whether to drop them from the type/API or leave them unused (favor removing if nothing else reads them). Menu Management, Employees, and Analytics pages get a dark-theme visual pass only (colors/spacing token alignment) -- no layout or interaction changes. Owner Console's `Layout.Sider` becomes tablet-responsive (collapses to a drawer/toggle pattern below a defined breakpoint) rather than the current fixed always-visible 230px sider.

## Acceptance criteria
- `tables` gains a persisted `zone` column (migration + model + validation + API resource output); existing table CRUD endpoints accept/return it
- `TableLayoutEditor`'s canvas is replaced by a card-grid component: stat row (Tables/Seats/Occupied), inline Add-table form (including Zone), color-coded rounded table cards (green/red/orange = available/occupied/reserved) grouped by zone heading
- Selecting a table shows a right-hand detail panel with its shape/seats/zone/server and Edit/Duplicate/Remove actions
- Table edit form includes a Zone field; existing shape/capacity fields preserved
- Menu Management, Employees, and Analytics pages visually match the new dark theme (from C-36); their existing layouts and interactions are otherwise unchanged
- Owner Console's sidebar collapses to a drawer/toggle pattern on tablet-width viewports; desktop behavior (expand/collapse toggle from C-31/C-34) unchanged
- Existing `OwnerPage.test.tsx`/`TableLayoutEditor.test.tsx` coverage updated for the new component; new tests cover zone grouping, card color-coding by status, and detail-panel actions; tsc -b clean, oxlint clean; backend tests pass, Pint clean
