# C-26: Analytics Dashboard UI -- Design

## Parent
Part of [[EP-23]] -- see [[DS-23]] for the umbrella rationale. Depends on [[US-24]] and [[US-25]] landing first; also consumes the existing `GET /api/time-entries` ([[EP-10]]/C-13).

## Problem
Once [[US-24]] and [[US-25]] exist, the Owner still has no way to see any of it -- there's no UI surfacing sales trends, best/worst sellers, attendance, or the inventory restock list.

## Approach
Add an "Analytics" entry to `OwnerPage`'s `NAV_ENTRIES` array ([[DS-16]]), alongside Table Layout, Menu Management, and Employees, with a new nested route (e.g. `/owner/analytics`) following the established pattern. Invoke the `dataviz` skill for chart type and styling decisions consistent with the brand theme (`frontend/src/theme.ts`). Build sections for: a sales trend chart (consuming [[US-24]]), a best/worst-seller ranked view (quantity and revenue, consuming [[US-24]]), an attendance/hours view (consuming the existing time-entries endpoint), and an inventory restock table with threshold override (consuming [[US-25]]).

## Acceptance criteria
- An "Analytics" entry appears in `OwnerPage`'s Sider/Menu navigation, without restructuring the existing Table Layout / Menu Management / Employees entries.
- A sales trend chart renders revenue over time from [[US-24]]'s endpoint.
- A best/worst-seller view shows menu items ranked by both quantity sold and revenue from [[US-24]]'s endpoint.
- An attendance/hours view renders data from the existing `GET /api/time-entries` endpoint.
- An inventory restock view shows current stock, suggested threshold, and shortfall per ingredient from [[US-25]]'s endpoint, with a control for the Owner to override a threshold.
- Chart type and color choices follow the `dataviz` skill's guidance and are visually consistent with the established brand theme.
- All data on this dashboard comes from [[US-24]], [[US-25]], or the existing time-entries endpoint -- no other data source.
