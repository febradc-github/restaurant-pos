# C-16: Owner Page -- Design

## Parent
Part of [[EP-14]] -- see [[DS-14]] for the umbrella rationale. Depends on [[US-15]] (routing + shared theme) landing first.

## Problem
`TableLayoutEditor` and `MenuManager` are currently rendered inline in `App.tsx` for a logged-in Owner, each with its own ad-hoc styling and no shared navigation. The Owner will soon also get Employee Management and an Analytics Dashboard (separate, not-yet-refined epics) -- the page shell built here needs room for those without restructuring.

## Approach
Build `OwnerPage` at the `/owner` route (established in C-15) using an Ant Design `Layout` with a `Menu` for navigating between sections (initially Table Layout and Menu Management; structured so additional menu items can be added later without a rewrite). Invoke `ui-ux-pro-max` for this page's specific layout/navigation choices within the C-15 shared theme. Fully rebuild `MenuManager`'s forms/tables (category + item CRUD, availability toggle) with Ant Design `Form`/`Table`/`Card`. `TableLayoutEditor`'s drag/resize canvas logic is kept as-is; only its toolbar/buttons/surrounding chrome are restyled with Ant Design primitives.

## Acceptance criteria
- `OwnerPage` exists at `/owner`, gated behind login as today, using the C-15 shared theme.
- An Ant Design `Layout`/`Menu` shell provides navigation between Table Layout and Menu Management, structured to accept additional sections later.
- `MenuManager` is fully rebuilt with Ant Design components (`Form`, `Table`, `Card`), preserving existing category/item CRUD, availability toggle, and the 409-on-delete-with-items behavior (C-4).
- `TableLayoutEditor`'s canvas drag/resize/add/delete interaction logic is unchanged; its toolbar and surrounding UI are restyled with Ant Design primitives.
- Owner-only gating (both UI visibility and existing API authorization) is unchanged.
