# C-35: Dark Theme Redesign & UX Overhaul (Owner Console, Cashier, Server) -- Design

## Problem

The app's current light terracotta Ant Design theme and per-page interaction patterns (Owner Console's canvas-based floor-plan editor, Cashier's unbounded order cards with no order identifiers or shift context, Server's wide-row item list with no visible cart) have accumulated real usability gaps that incremental audits (C-28 through C-34) deliberately did not address, because those audits were scoped to patch-in-place fixes, not redesign. The user has supplied three reference designs (Owner Console, Cashier, Server) specifying a cohesive dark theme and several concrete UX fixes:

- Cashier: duplicate table cards are visually indistinguishable (two "Table 1" cards with nothing to tell them apart), a real risk of confirming the wrong payment; no per-line prices; long orders (12+ items) grow the card unboundedly with no visible total/payment controls; no shift-level situational awareness (open orders, pending total, paid today); no search/sort on a busy floor.
- Server: item name and quantity stepper sit at opposite ends of a wide row, forcing the server's eye/finger across the full screen per item; the menu is a flat list with no categorization, unusable once it grows past a handful of items; table selection is a dropdown instead of one-tap chips; there is no visible cart/running total/submit action while building an order, and no way to attach a kitchen note (e.g. "no onions").
- Owner Console: the Table Layout page's drag/resize canvas doesn't match the requested zone-grouped, at-a-glance card view, and none of the four Owner Console pages have been asked to support tablet/mobile widths.

None of this is achievable as a further patch-in-place pass -- it changes core interaction models (canvas -> card grid, dropdown -> chips, no-cart -> persistent summary panel) and the color system itself.

## Architecture

**Supersedes [[adr-011-patch-ant-design-in-place-over-rebuild]] for these three pages specifically.** ADR-011 chose patch-over-rebuild for C-28 and explicitly named its own exception: "The right time for a full rebuild would be a future major visual redesign, not a quality/consistency pass on a working system." This ticket is that redesign. It does not reopen or invalidate C-28/C-30/C-31/C-32/C-33/C-34's already-shipped fixes elsewhere (Login, Kitchen, Employees/Analytics layout, the C-34 contrast/truncation fix) -- those pages inherit the new theme but keep their current layouts and interactions.

**Reverses one exception in [[AR-frontend-design-system]]:** that note records TableLayoutEditor's drag/resize canvas as a deliberate keep ("domain-specific logic, not a typical form/table UI... only surrounding chrome restyled"). This ticket removes the canvas entirely in favor of a zone-grouped card grid, because the requested design has no canvas/positioning concept at all -- table arrangement becomes card order within a named zone, not x/y coordinates. Free-form floor-plan positioning is lost as a capability; this is accepted as part of the redesign, not an oversight.

**Affected components:**
- `frontend/src/theme.ts` / `frontend/src/App.tsx` (`ConfigProvider`) -- single global theme swapped to a dark palette, keeping the `#C2410C`-family terracotta as the accent/primary color for buttons, active nav, selected chips.
- `frontend/src/index.css` -- the leftover pre-C-29 `@media (prefers-color-scheme: dark)` block and the C-34 `.app__session` background shield become candidates for removal/simplification once a real dark `ConfigProvider` exists; verified during implementation, not assumed here.
- `frontend/src/components/OwnerPage.tsx`, `OwnerPage.css`, `TableLayoutEditor.tsx` (replaced by a new card-grid component), `MenuManager.tsx`, `EmployeeManager.tsx`, `AnalyticsDashboard.tsx` (theme-only pass).
- `frontend/src/components/Checkout.tsx`, `CashierPage.tsx`.
- `frontend/src/components/OrderTaking.tsx`, `TakeOrdersPage.tsx`.
- `frontend/src/types/table.ts` (+ `zone` field), `frontend/src/types/order.ts` (+ `created_at`, kitchen note field).
- Backend: `tables` migration adding `zone` (string, nullable or default), `order_items` (or `orders`) migration adding a notes column, plus model/controller/validation updates on both. Table's `TableController`/`OrderController` (exact names TBD at spec time) need the new fields in their request validation and resource output.

## Approach

One epic (`type: epic`), broken down via `/cadence:breakdown` into per-page/per-concern stories so each lands as an independently reviewable diff:
1. App-wide dark theme foundation (ConfigProvider palette, index.css cleanup/reconciliation, verify C-34's fix still needed or simplifies away).
2. Owner Console Table Layout rebuild (canvas removal, card-grid component, zone field end-to-end) + dark-theme pass on Menu/Employees/Analytics.
3. Cashier/Checkout redesign (order identity + elapsed time, line-item prices, truncation, shift header, search/sort, demoted cancel).
4. Server/Take-Orders redesign (compact item cards, category grouping + filters, chip-based table selection, persistent order-summary panel, kitchen notes end-to-end).
5. Responsive/tablet pass across the above (may be folded into each story's acceptance criteria rather than a separate story -- decided at breakdown time).

Each story gets its own spec with concrete acceptance criteria, since each is independently sizeable (some touch the backend, some are pure frontend).

## Trade-offs considered

- **Scoped dark theme (Owner Console only) vs. app-wide:** rejected app-wide-only... resolved via brainstorm dialogue in favor of **app-wide**, since a single global `ConfigProvider` already exists and a scoped override would fragment the design system further (two themes to maintain) for no clear benefit -- none of the reference images suggested Cashier/Server/Login should stay light.
- **Keep the floor-plan canvas as an alternate view alongside the new card grid:** rejected via brainstorm dialogue -- doubles the maintenance surface (two table-arrangement UIs backed by different data shapes) for a capability (free-form positioning) the user did not ask to keep.
- **Kitchen notes / table zone as frontend-only (unpersisted) placeholders vs. real backend fields:** rejected the placeholder approach via brainstorm dialogue -- confirmed building both as real, persisted features now rather than faking them and creating a follow-up-ticket debt.

## Acceptance criteria

(Outcome-level; per-page checkable criteria are established per child story via `/cadence:breakdown` + `/cadence:spec`.)

- The entire app renders under a new dark Ant Design theme via the existing single `ConfigProvider`, retaining the terracotta/orange brand accent for primary actions and active/selected states; no page regresses to unreadable contrast (build on the dark-on-dark lesson from C-34).
- Owner Console's Table Layout page is a zone-grouped, color-coded table card grid (stat row, inline add-table form, Available/Occupied/Reserved color coding, right-hand detail panel with Edit/Duplicate/Remove) with the canvas-based drag/resize editor removed; `Table` gains a persisted `zone` field end-to-end (migration, API, frontend type, UI).
- Menu Management, Employees, and Analytics pages carry the new dark theme with their existing layouts/interactions otherwise unchanged.
- Cashier/Checkout shows, per order card: an order number and elapsed time since placement; right-aligned per-line prices with a total footer; a confirm-payment button that repeats the total; truncation with a "+N more items" expander for long orders; a shift-summary header (open orders, pending total, paid today); search (table or item) and sort (e.g. oldest-first) controls; and a visually demoted (quiet/text-style) cancel action. All C-32-shipped safeguards (Popconfirm on cancel, loading/disabled state during requests, `size="large"` controls) are preserved.
- Server/Take-Orders shows compact item cards (name, price, and quantity stepper together), a menu grouped into category sections with header + filter chips + search, table selection as one-tap chips (selected table shown in the brand accent color), and a persistent order-summary panel (selected items, running total, a kitchen-notes field, a prominent "Send to kitchen" action); items with quantity > 0 show an accent border. `order_items` (or equivalent) gains a persisted kitchen-note field end-to-end.
- All three redesigned pages plus the Owner Console shell remain usable at tablet width; the order-summary panel and/or sidebar collapse into a compact bottom-bar/drawer pattern below a defined breakpoint (exact breakpoint(s) set per child story's spec).
- Existing and new frontend test suites pass for every touched page, `tsc -b` clean, oxlint clean; backend tests pass and Pint is clean for the new `zone`/kitchen-note fields.
