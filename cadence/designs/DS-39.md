# C-39: Server/Take-Orders Redesign -- Design

## Parent
Part of [[EP-35]] -- see [[DS-35]] for the umbrella rationale. Depends on [[US-36]] (dark theme foundation) landing first.

## Problem
`OrderTaking.tsx` lays item name and quantity stepper at opposite ends of a wide row, forcing the server's eye/finger across the full screen per item; the menu is a flat list with no categorization (`MenuItem` has `category_id` but no resolved category name in the type today); table selection is a searchable `Select` dropdown instead of one-tap chips; there is no visible cart/running total/submit affordance while building an order; and there is no way to attach a kitchen note (`OrderLineItem`/`NewOrderItem` carry only `menu_item_id`/`quantity` today).

## Approach
Redesign item cards so name, price, and quantity stepper sit together (compact card), not spread across a wide row. Join `MenuItem.category_id` to `Category.name` client-side (Category data already fetched elsewhere in the app) to group the menu into named sections with headers, add tappable category filter chips and a search box. Replace the table `Select` with tappable chips; selected table highlighted in the brand accent color. "Assigned server" next to the selected table chip uses the current session's logged-in user (already available client-side, no backend change). "Guest count" has no backing field today (confirmed via backend grep: no `guest_count`/`party_size` column anywhere) -- decide at implementation time whether to add a minimal `guest_count` field (small migration on `orders` or a per-visit concept) or omit it from this pass; either is acceptable, but do not silently fake a number in the UI. Add a persistent right-hand order-summary panel: selected items, running total, a kitchen-notes free-text field, and a prominent "Send to kitchen" action. Kitchen notes require a new persisted field on order items (migration + model + validation + API on `order_items`, or wherever the item-level note is added; a new `notes`/`special_instructions` column), plus frontend `NewOrderItem`/`OrderLineItem` type updates and wiring through the send-to-kitchen submission. Items with quantity > 0 get an accent border in the grid. On narrow/tablet viewports, the order-summary panel collapses into a compact bottom bar (e.g. "8 items · $32.50 · Send").

## Acceptance criteria
- Item cards show name, price, and quantity stepper together in a compact layout (not split across a wide row)
- Menu is grouped into category sections with headers; tappable category filter chips and a search box narrow the visible items
- Table selection uses tappable chips instead of a dropdown; the selected table is highlighted in the brand accent color and shows the current session's server name beside it
- Guest count is either backed by a real new field (documented choice) or explicitly omitted from this pass -- not faked with placeholder data
- `order_items` (or the appropriate table) gains a persisted kitchen-note field: migration, model, validation, and API serialization
- A persistent right-hand order-summary panel shows selected items, running total, a kitchen-notes input, and a "Send to kitchen" action that submits the note(s) along with the order
- Menu items with quantity > 0 show an accent border in the grid
- On narrow/tablet viewports, the order-summary panel collapses into a compact bottom bar summarizing item count, total, and the send action
- New/updated tests cover category grouping/filtering, chip-based table selection, kitchen-note persistence end-to-end, and the responsive bottom-bar collapse; tsc -b clean, oxlint clean; backend tests pass, Pint clean
