# C-38: Cashier/Checkout Redesign -- Design

## Parent
Part of [[EP-35]] -- see [[DS-35]] for the umbrella rationale. Depends on [[US-36]] (dark theme foundation) landing first.

## Problem
`Checkout.tsx`'s order cards are keyed by table label only, so duplicate-table orders (two open "Table 1" orders) are visually indistinguishable -- a real payment-confirmation risk. There are no per-line prices, no order-level total-vs-payment context beyond a bare total, unbounded card growth for long orders (the existing 12-item case), and no shift-level or search/sort affordances for a busy floor.

## Approach
Add `created_at` to the frontend `Order` type (already serialized by the backend `OrderController`, just not typed today) and display order number (`order.id`) + elapsed time on each card. Add a right-aligned price per line item and a clear total footer. Confirm-payment button label repeats the total. Orders beyond a threshold item count show the first few lines plus a "+N more items" expander. Add a shift-summary header (open order count, pending total, paid today) sourced from the existing orders/payments data already available to the page (no new backend endpoint expected -- confirm during implementation whether the existing list endpoint carries enough to derive these client-side, or a small aggregate is needed). Add a search input (table or item) and a sort control (e.g. oldest-first) over the existing order list. Demote "Cancel order" to a quiet/text-style button, keeping its existing Popconfirm and loading/disabled request-state behavior from C-32 intact. Follow whatever currency-formatting convention already exists in the codebase (check before introducing a new symbol/format).

## Acceptance criteria
- Each order card shows an order number (`order.id`) and elapsed time since `created_at`
- Line items show a right-aligned price; the card has a clear total footer
- The confirm-payment button's label repeats the order total
- Orders with more line items than the established threshold (matching today's 12-item worst case) show a truncated list plus a "+N more items" expander instead of growing the card unbounded
- A shift-summary header shows open order count, pending total, and paid-today, computed from data already available to the page (or a minimal new aggregate if that's not sufficient -- confirmed during implementation)
- A search input filters visible orders by table or item; a sort control (e.g. oldest-first) reorders them
- "Cancel order" is visually demoted to a quiet/text-style button; the existing Popconfirm confirmation and loading/disabled request state (C-32) are preserved
- Page remains usable at tablet width (card grid reflows, no horizontal scroll/clipping)
- New/updated tests cover order identity+elapsed time, truncation/expander, search/sort, and the preserved cancel-confirmation behavior; tsc -b clean, oxlint clean
