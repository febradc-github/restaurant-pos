# C-28: Frontend GUI Quality & Consistency Pass -- Design

## Problem

The Owner reported a broken screen (Table Layout page rendering its "Floor Plan"
heading one character per line, plus a stray misplaced element) and asked more
broadly to "fix all GUI problems, make sure that we are using Ant Design, make it
beautiful." Two distinct problems sit under that ask:

1. A concrete regression in the app shell: `frontend/src/App.tsx` wraps every
   route in `<main id="center">`, and `App.css`'s `#center` rule carries a
   leftover `create-vite`-starter-template `place-items: center` declaration.
   That forces every routed page's root element to shrink-to-fit instead of
   stretch to fill available width, cascading into collapsed/garbled layout --
   confirmed via user screenshot and a temporary diagnostic edit. `App.css`
   also still carries other dead starter CSS (`.hero`, `#next-steps`, `#docs`,
   `#spacer`, `.framework`, `.vite`, `.base`, and `#root`'s landing-page
   `width: 1126px` constraint) never removed when the app was repurposed from
   the scaffold into the real POS product.
2. No systematic design-quality pass has ever been run against the finished
   product. Every page was built with Ant Design (C-14) and later features
   layered on (C-20, C-23), but nothing has audited the *result* end-to-end
   for accessibility, spacing/typography consistency, or visual polish.

## Architecture

Sits inside [[AR-frontend-design-system]] (C-14's Ant Design + ConfigProvider
routing architecture) without contradicting it: that architecture already
established Ant Design as the library and `frontend/src/theme.ts` as the single
theme source of record. The app-shell bug in `App.tsx`/`App.css` predates and
sits outside that per-page antd work entirely -- it was never touched by C-14's
page rebuilds, which explains why it survived undetected. This epic does not
introduce a new architecture; it closes a gap in the existing one (cleaning up
the shell) and adds a verification pass (the audit) on top of it.

## Approach

1. **Fix the app-shell regression.** Remove the dead Vite-starter CSS/markup
   from `App.tsx`/`App.css` (the `#center` wrapper's `place-items: center`,
   and the unused `.hero`/`#next-steps`/`#docs`/`#spacer`/`.framework`/`.vite`/
   `.base` rules and `#root`'s landing-page width constraint), confirming no
   regression to `Login`'s centered appearance (it has its own `Login.css` and
   appears self-contained -- confirmed during implementation).
2. **Run a systematic `ui-ux-pro-max` audit** of every screen -- Login, Owner
   Console (Table Layout, Menu Management, Employees, Analytics), Cashier
   (Checkout), Take-Orders (OrderTaking), Kitchen (KitchenDisplay +
   KitchenClockPad) -- against accessibility (contrast, touch targets, focus
   states), spacing/typography scale, Ant Design token/theme consistency, and
   general visual polish. The audit produces a concrete, itemized findings
   list per page, not a vague "make it better."
3. **Break the findings into per-page/area stories** via `/cadence:breakdown`
   once the audit is complete, so each fix is independently reviewable and
   scoped rather than one sprawling diff.

## Trade-offs considered

Rebuilding pages from scratch against `ui-ux-pro-max` guidance vs. auditing
the existing Ant Design implementation and patching findings: patch-in-place
was chosen. C-14 already established a working, tested Ant Design foundation
(`AR-frontend-design-system`); a full rebuild would risk regressing tested
functionality across 7+ screens for no benefit over a targeted audit-and-fix
pass, and is over-engineering relative to the actual problem (a shell bug plus
unknown, not-yet-identified polish gaps).

## Acceptance criteria

- No dead/leftover starter-template CSS or markup remains in the app shell
  (`App.tsx`/`App.css`); no routed page's layout is affected by unintended
  shrink-to-fit collapse (the Table Layout regression is fixed and verified).
- Every screen (Login, Owner Console's 4 sections, Cashier, Take-Orders,
  Kitchen) has been audited against `ui-ux-pro-max` guidelines for
  accessibility, spacing/typography consistency, and Ant Design token usage.
- Every concrete finding from the audit is either fixed or explicitly logged
  as an out-of-scope follow-up with a stated reason.
- The full frontend test suite passes with no regressions on every touched
  page.
