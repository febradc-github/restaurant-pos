# C-36: App-Wide Dark Theme Foundation -- Design

## Parent
Part of [[EP-35]] -- see [[DS-35]] for the umbrella rationale.

## Problem
The app has one global antd `ConfigProvider` (`frontend/src/theme.ts`) using a light palette (`colorBgLayout: #FAFAFA`, terracotta `colorPrimary: #C2410C`). C-35's three page redesigns (C-37/C-38/C-39) all assume a dark theme is already in place; this story lands that foundation first so the page stories build on real dark tokens instead of each inventing their own.

## Approach
Switch `theme.ts`'s `ConfigProvider` to antd's dark algorithm with dark neutral tokens (`colorBgLayout`, `colorBgContainer`, etc.), keeping the terracotta family as `colorPrimary` so buttons/active states/accents stay on-brand against the new dark background. Reconcile `index.css`'s leftover pre-C-29 `@media (prefers-color-scheme: dark)` block -- once the antd theme itself is dark, that OS-preference-driven CSS is likely redundant or actively conflicting and should be simplified or removed. Re-verify C-34's `.app__session` `theme.useToken()` background fix under the new theme (it may already resolve correctly for free, or may need adjustment). Spot-check every existing route (Login, Owner Console's four pages as they exist today, Cashier, Take-Orders, Kitchen) for contrast regressions before considering this done -- this story does not redesign any page's layout, only its color tokens.

## Acceptance criteria
- `theme.ts`'s `ConfigProvider` uses a dark palette (dark algorithm + dark neutral tokens) with the existing terracotta `#C2410C`-family color retained as `colorPrimary`
- `index.css`'s leftover `@media (prefers-color-scheme: dark)` block is removed or reconciled so it no longer fights the app's own theme (no OS-preference-driven flip separate from the app's actual theme)
- C-34's session-bar background fix (`App.tsx` `SessionBar`) re-verified under the new theme; simplified if the dark ConfigProvider now makes the explicit `theme.useToken()` background shield unnecessary, left as-is with a note if still needed
- Every existing route (Login, Owner Console, Cashier, Take-Orders, Kitchen) renders with adequate text/background contrast under the new theme -- no dark-on-dark or light-on-light regressions introduced by the palette swap alone (page layouts are unchanged in this story)
- All existing frontend tests pass under the new theme; tsc -b clean, oxlint clean
