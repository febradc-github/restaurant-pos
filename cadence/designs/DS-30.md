# C-30: Login Page UI Audit & Fixes -- Design

## Parent
Part of [[EP-28]] -- see [[DS-28]] for the umbrella rationale.

## Problem
No systematic design-quality pass has ever been run against the Login screen.
It should be checked against `ui-ux-pro-max` guidelines now that the app-shell
regression ([[US-29]]) is fixed, since that fix changes how Login is laid out
within the app shell.

## Approach
Run the `ui-ux-pro-max` skill's audit checklist against `Login.tsx`/
`Login.css`: accessibility (contrast, focus states, keyboard nav, touch
target sizing for the login form's inputs/button), typography/spacing scale
consistency with the rest of the app's Ant Design theme, and Ant Design token
usage (no raw hex colors bypassing `theme.ts`). Fix concrete findings; log
anything deliberately deferred with a reason.

## Acceptance criteria
- Login screen audited against `ui-ux-pro-max` guidelines: accessibility
  (contrast ratios, focus states, keyboard navigation, touch target sizes),
  typography/spacing consistency, and Ant Design token usage.
- All concrete findings from the audit are fixed, or explicitly logged in
  this item's notes as an out-of-scope follow-up with a stated reason.
- The full frontend test suite passes with no regressions on Login.
