# C-13: Forgotten Clock-Out Auto-Close & Attendance Queries -- Design

## Parent
Part of [[EP-10]] -- see [[DS-10]] for the umbrella rationale.

## Problem
Any role (Cashier, Server via [[DS-11]], or Kitchen via [[DS-12]]) can end up with a `time_entries` row that never gets a `clock_out` -- a device loses connection, a shift ends without logout, or a PIN clock-out is never entered. Left unresolved, these indefinitely-open rows would corrupt the payroll/hours data this epic exists to produce. The owner also needs a way to query attendance data, since it feeds the not-yet-built analytics dashboard epic.

## Approach
Add a configurable daily cutoff (config/env value). A scheduled Laravel job runs at that cutoff, finds every `time_entries` row still open (`clock_out IS NULL`) at or before it, sets `clock_out` to the cutoff time and `auto_closed = true`. Add a query endpoint/scope that filters `time_entries` by `user_id`, `role`, and a date range, returning each row's `auto_closed` status -- a data surface only, no dashboard UI.

## Acceptance criteria
- A configurable daily cutoff exists (e.g. env/config value) that determines when auto-close runs.
- A scheduled job closes every `time_entries` row with `clock_out IS NULL` past the cutoff, setting `clock_out` to the cutoff time and `auto_closed = true`.
- Rows closed by the job are distinguishable from normally-closed rows via `auto_closed`.
- The job leaves entries that are still legitimately open and not yet past the cutoff untouched (a shift in progress is not closed early).
- An endpoint/query scope allows filtering `time_entries` by `user_id`, `role`, and date range, returning `auto_closed` status per row -- no dashboard or reporting UI is built here, this is a data surface for the later analytics epic.
- Job behavior (closes only past-cutoff open entries, correct `auto_closed` flagging) is covered by tests.
