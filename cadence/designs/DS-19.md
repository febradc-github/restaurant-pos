# C-19: Kitchen Page -- Design

## Parent
Part of [[EP-14]] -- see [[DS-14]] for the umbrella rationale. Depends on [[US-15]] (routing + shared theme) landing first.

## Problem
`KitchenDisplay` and `KitchenClockPad` are currently rendered inline in `App.tsx`, always visible with no login per the C-6/C-12 design, but styled ad-hoc and disconnected from the rest of the redesign. This is the one page where routing must NOT introduce a login gate.

## Approach
Build `KitchenPage` at the `/kitchen` route (established in C-15), explicitly ungated -- no route guard on this route, matching adr-008-server-login-kitchen-pin-attendance. Invoke `ui-ux-pro-max` for this page's layout within the C-15 shared theme. Fully rebuild `KitchenDisplay` (live order list, mark-ready) and `KitchenClockPad` (PIN-pad overlay) with Ant Design components, keeping `KitchenClockPad`'s independent state (it must not gate or block the order view) unchanged in behavior.

## Acceptance criteria
- `KitchenPage` exists at `/kitchen` with no login required -- explicit regression check against adr-008-server-login-kitchen-pin-attendance and the C-6/C-12 behavior.
- `KitchenDisplay` is fully rebuilt with Ant Design components, preserving fetch-on-mount, live WebSocket order updates, and mark-ready behavior (C-6).
- `KitchenClockPad` is fully rebuilt with Ant Design components, preserving its PIN-based clock-in/out toggle and its independence from the order list's state (C-12) -- entering a PIN must not navigate away from or interrupt the live order view.
