# C-33: Kitchen UI Audit & Fixes -- Design

## Parent
Part of [[EP-28]] -- see [[DS-28]] for the umbrella rationale.

## Problem
The Kitchen screen (`KitchenDisplay` + the `KitchenClockPad` PIN overlay,
C-6/C-12/C-19) has never had a systematic design-quality pass. It has
existing documented constraints (at-a-distance readability for a
wall-mounted/counter display, large touch targets for gloved/wet-hand use)
that any audit must respect rather than override.

## Approach
Run the `ui-ux-pro-max` skill's audit checklist against `KitchenDisplay` and
`KitchenClockPad`, explicitly preserving their existing large-touch-target
(3.5rem minimum) and at-a-distance-readability design intent -- the audit
should find polish/consistency gaps, not undo deliberate prior decisions.
Check accessibility, spacing/typography consistency, and Ant Design token
usage. Fix concrete findings; log anything deliberately deferred with a
reason.

## Acceptance criteria
- `KitchenDisplay` and `KitchenClockPad` audited against `ui-ux-pro-max`
  guidelines: accessibility, spacing/typography consistency, Ant Design
  token usage, visual polish -- without regressing the existing large-touch-
  target / at-a-distance-readability design intent.
- All concrete findings from the audit are fixed, or explicitly logged in
  this item's notes as an out-of-scope follow-up with a stated reason.
- The full frontend test suite passes with no regressions on the Kitchen
  screen.
