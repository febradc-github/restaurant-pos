# C-15: Foundation: Routing, Ant Design & Brand Theme -- Design

## Parent
Part of [[EP-14]] -- see [[DS-14]] for the umbrella rationale.

## Problem
Nothing in the frontend today can host four separate routed pages or a shared visual language: there is no router and no component library. Every other C-14 story depends on this foundation existing first.

## Approach
Add `react-router-dom` and `antd`. Invoke `ui-ux-pro-max` to choose a custom brand color palette and typography, encoded as a single `ConfigProvider` theme object shared by every page. Build the route shell: `/login`, `/owner`, `/cashier`, `/take-orders`, `/kitchen`, replacing `App.tsx`'s inline role-conditionals with route guards that reuse the existing session state (Owner/Cashier/Server gated per C-2/C-7/C-11; Kitchen ungated per adr-008). Rebuild `Login.tsx` with Ant Design (`Form`, `Input`, `Button`, `Card`).

## Acceptance criteria
- `react-router-dom` and `antd` are added as dependencies.
- Routes exist for `/login`, `/owner`, `/cashier`, `/take-orders`, `/kitchen`.
- Owner and Cashier routes are gated behind login exactly as today; Take-Orders is gated behind login exactly as C-11 established; Kitchen's route is reachable with no login required (explicit regression check against adr-008).
- A single shared `ConfigProvider` theme (custom brand color palette + typography, chosen via `ui-ux-pro-max`) is established and applied at the app root, ready for every subsequent page story to consume.
- `Login.tsx` is rebuilt using Ant Design components, preserving existing login behavior (identifier + password, error display on failure).
- No backend changes; existing `/api/login` contract is unchanged.
