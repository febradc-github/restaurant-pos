# C-11: Server & Cashier Login-Based Time Tracking -- Design

## Parent
Part of [[EP-10]] -- see [[DS-10]] for the umbrella rationale.

## Problem
Server (waiter) currently has no login at all, and Cashier's existing login/logout ([[app-http-controllers-api-authcontroller-php]]) has no attendance side effect. Neither role produces the time-in/time-out data the owner needs for payroll and shift accountability.

## Approach
Add the `time_entries` table/model (`user_id`, `role`, `clock_in`, `clock_out` nullable, `auto_closed` boolean default false). Give Server real `UserRole::Server` User accounts authenticating through the same Sanctum login endpoint Cashier already uses. Hook both Cashier's and Server's login action to create a `time_entries` row (`clock_in = now()`) and their logout action to set `clock_out = now()` on the caller's open row. On the frontend, gate the Take-Orders page behind the existing `Login`/session pattern already used for Cashier's Checkout page, so a waiter must log in to reach it and logging out ends their session there.

## Acceptance criteria
- `time_entries` table/model exists with `user_id`, `role`, `clock_in`, `clock_out` (nullable), `auto_closed` (boolean, default false).
- `UserRole::Server` accounts can authenticate via the same Sanctum login endpoint Cashier uses today.
- A Server login creates a `time_entries` row with `clock_in = now()`; a Server logout sets `clock_out = now()` on that user's open row.
- Cashier's existing login/logout is retrofitted to do the same (create/close a `time_entries` row) without changing Cashier's existing auth behavior or response shape.
- The Take-Orders frontend page requires login, following the same session-gating pattern already used for Cashier's Checkout page; logging out returns to the login screen.
- `time_entries` rows are queryable by `user_id` and `role` (basic query scope; date-range filtering and any reporting UI belong to the later analytics epic, out of scope here).
