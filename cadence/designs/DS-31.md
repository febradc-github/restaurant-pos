# C-31: Owner Console UI Audit & Fixes -- Design

## Parent
Part of [[EP-28]] -- see [[DS-28]] for the umbrella rationale.

## Problem
The Owner Console (`OwnerPage.tsx` shell plus its four sections -- Table
Layout, Menu Management, Employees, Analytics, built across C-14/C-20/C-23)
has never had a systematic design-quality pass. This is also where the
originally reported bug was visually caught, so it needs the most careful
re-check after [[US-29]]'s shell fix lands.

## Approach
Run the `ui-ux-pro-max` skill's audit checklist against the shared
`OwnerPage` shell (Sider/Menu/Header/Content chrome) and each of its four
routed sections: `TableLayoutEditor`, `MenuManager`, the Employees section,
and `AnalyticsDashboard`. Check accessibility, spacing/typography
consistency, Ant Design token usage, and general visual polish per screen.
Fix concrete findings; log anything deliberately deferred with a reason.
Re-verify the original reproduction case (Table Layout's "Floor Plan"
heading and canvas) renders correctly, since that's this epic's origin bug.

## Acceptance criteria
- The shared `OwnerPage` shell (Sider, Header, nav) and all four sections
  (Table Layout, Menu Management, Employees, Analytics) are audited against
  `ui-ux-pro-max` guidelines: accessibility, spacing/typography consistency,
  Ant Design token usage, visual polish.
- All concrete findings from the audit are fixed, or explicitly logged in
  this item's notes as an out-of-scope follow-up with a stated reason.
- The Table Layout page's "Floor Plan" heading and 800x600 canvas are
  confirmed rendering correctly (the epic's origin bug, re-verified here).
- The full frontend test suite passes with no regressions across all four
  Owner Console sections.
