# C-14: Role-Based Page Architecture & Ant Design Redesign -- Design

## Problem

`frontend/src/App.tsx` is a single component that conditionally renders feature components inline based on `session.user.role` -- there is no router, no shared design system, and each component (`TableLayoutEditor`, `MenuManager`, `Checkout`, `OrderTaking`, `KitchenDisplay`, `KitchenClockPad`, `Login`) has its own hand-written CSS file with no consistent visual language. The owner wants four genuinely separate, routed pages (Owner, Cashier, Take-Orders/Server, Kitchen) and a full GUI redesign using Ant Design (antd).

This epic is sequenced ahead of two not-yet-refined epics from the same "digital transformation" initiative -- Owner Employee Management and an Owner Analytics Dashboard -- so those land directly inside the new page architecture instead of being built once in the current ad-hoc structure and redesigned again immediately after.

## Architecture

Purely frontend; no backend changes. Affects every existing frontend component and `App.tsx`'s role-dispatch logic (see [[src-app-tsx]], [[src-components-login-tsx]]).

- **Routing**: introduces `react-router-dom` (not present in the project today). The deployed static server ([[deploy-static-server-js]]) already does SPA fallback (404 -> `index.html`), confirmed safe for client-side routing without any change to `deploy/ecosystem.config.js` or the static server itself.
- **Component library**: introduces `antd` (Ant Design). No prior design-system note exists for this project (`AR-*` search found none) -- this establishes the first one.
- **No-login constraint preserved**: [[adr-008-server-login-kitchen-pin-attendance]] established that the Kitchen order display must remain gate-free. `KitchenPage` must not introduce a route guard on the order view; only the existing PIN-pad overlay (already gated by PIN, not by routing) stays as-is.
- **Auth-gating preserved**: Server (Take-Orders) and Cashier routes stay gated behind the session established in C-7/C-11 -- routing replaces `App.tsx`'s inline conditionals with route guards that check the same `session` state, not a new auth mechanism.

## Approach

1. **Foundation** (routing + antd + brand + Login): add `react-router-dom` and `antd`; establish a shared theme via a single `ConfigProvider` theme object encoding a custom brand palette (colors/typography), chosen via the `ui-ux-pro-max` design skill. Redesign `Login.tsx` with Ant Design (`Form`, `Input`, `Button`, `Card`). Build the route shell: `/login`, `/owner`, `/cashier`, `/take-orders`, `/kitchen`, with route guards reusing existing session state (owner/cashier/server gated; kitchen ungated).
2. **Per-page rebuild** (one story per role page), each invoking `ui-ux-pro-max` for that page's specific layout/component choices within the shared theme established in the foundation:
   - `OwnerPage`: hosts `TableLayoutEditor` + `MenuManager` under an Ant Design `Layout`/`Menu` shell with room for future sections (Employee Management, Analytics Dashboard land here as later epics without restructuring this shell). Full visual rebuild of `MenuManager`'s forms/tables into Ant Design `Form`/`Table`/`Card`. `TableLayoutEditor`'s drag/resize canvas logic is kept as-is (domain-specific interaction, not a typical form/table UI) -- only its toolbar/buttons/panels are restyled with Ant Design primitives.
   - `CashierPage`: hosts `Checkout`, fully rebuilt with Ant Design components (payment method selection, confirmation, cancel).
   - `TakeOrdersPage`: hosts `OrderTaking`, fully rebuilt with Ant Design components.
   - `KitchenPage`: hosts `KitchenDisplay` + `KitchenClockPad`, fully rebuilt with Ant Design components; the order view itself remains no-login, and the PIN-pad overlay keeps its own independent state (per [[adr-008-server-login-kitchen-pin-attendance]] and the C-12 design) -- routing must not gate it.

## Trade-offs considered

- **Page shell only (restyle chrome, leave component internals as-is)** -- rejected. The owner asked for a "full redesign," and re-hosting unstyled components inside new page chrome would leave a visibly inconsistent product (new nav, old forms).
- **Antd default theme instead of a custom brand palette** -- rejected per explicit preference; a custom palette is established once in the foundation story via `ui-ux-pro-max` and reused as shared theme tokens across all pages.
- **Invoking `ui-ux-pro-max` once up front for the whole epic** -- rejected per explicit preference; it's invoked per page/story instead, each page's specific design decided in the context of implementing that page (within the shared theme/tokens the foundation story establishes).

## Acceptance criteria

- `react-router-dom` is added and four authenticated routes exist (`/owner`, `/cashier`, `/take-orders`, `/kitchen`) plus `/login`, replacing `App.tsx`'s inline role-conditional rendering.
- Owner and Cashier routes remain gated behind login exactly as today (C-2/C-7); Server (`/take-orders`) remains gated behind login exactly as C-11 established; Kitchen's order display (`/kitchen`) remains reachable with no login required, unchanged from the C-6/C-12 behavior -- this is an explicit regression check.
- `antd` is installed and a single shared theme (via `ConfigProvider`), encoding a custom brand color palette and typography chosen via `ui-ux-pro-max`, is applied consistently across all five pages (login + 4 role pages).
- `Login.tsx` is rebuilt with Ant Design components.
- `OwnerPage` hosts `TableLayoutEditor` (canvas/drag-resize logic unchanged, chrome restyled) and `MenuManager` (fully rebuilt with Ant Design `Form`/`Table`/`Card`) under a page shell with navigation designed to accommodate additional sections later without restructuring.
- `CashierPage` hosts `Checkout`, fully rebuilt with Ant Design components, preserving existing checkout/payment-confirmation/cancellation behavior (C-7).
- `TakeOrdersPage` hosts `OrderTaking`, fully rebuilt with Ant Design components, preserving existing order-taking behavior (C-6) and login-gating (C-11).
- `KitchenPage` hosts `KitchenDisplay` and `KitchenClockPad`, both fully rebuilt with Ant Design components, preserving live order updates, mark-ready, and independent PIN-pad clock-in/out behavior (C-6/C-12) with the order view remaining ungated.
- No backend changes are required or made; all existing API contracts are unchanged.
