# C-21: Employee Management API -- Design

## Parent
Part of [[EP-20]] -- see [[DS-20]] for the umbrella rationale.

## Problem
No production path exists to create, list, modify, or deactivate a `User`. The backend has no employee lifecycle at all -- `OwnerController` is a stub.

## Approach
Add an `active` boolean column to `users` (default `true`). Add `EmployeeController` (Owner-gated: `auth:sanctum` + `role:owner`):
- `index` -- list all employees with role and active status.
- `store` -- create an employee: `name`, `role`, and role-appropriate credential (`password` for Owner/Cashier/Server, unique 6-digit `pin` for Kitchen).
- `update` -- change an employee's role and/or reset their credential.
- `deactivate` / `reactivate` -- toggle `active`, rejecting a deactivation attempt that targets the caller's own account or the last remaining active Owner.

Extend `AuthController::login` (Cashier/Server/Owner) and `KitchenClockController::clock` (Kitchen) to also reject when the resolved user's `active` is `false`, using the same generic-rejection style already established in [[EP-10]] (no extra information revealed about why).

## Acceptance criteria
- `active` boolean column exists on `users`, default `true`.
- Owner-gated `POST` endpoint creates an employee with name, role, and the role-appropriate credential (password for Owner/Cashier/Server; unique 6-digit PIN for Kitchen); validation rejects a duplicate email (login roles) or duplicate PIN (Kitchen).
- Owner-gated `GET` endpoint lists all employees with role and active status.
- Owner-gated endpoint updates an employee's role and/or resets their credential.
- Owner-gated endpoints deactivate/reactivate an employee; deactivating/reactivating never touches that user's historical `time_entries` or `orders` rows.
- Deactivating the caller's own account is rejected with a clear error.
- Deactivating the last remaining active Owner account is rejected with a clear error.
- `AuthController::login` rejects a deactivated Cashier/Server/Owner using the same generic-rejection style as an invalid credential.
- `KitchenClockController::clock` rejects a deactivated Kitchen employee's PIN using the same generic-rejection style as an unrecognized PIN.
