# C-32: Cashier & Take-Orders UI Audit & Fixes -- Design

## Parent
Part of [[EP-28]] -- see [[DS-28]] for the umbrella rationale.

## Problem
The Cashier (`CashierPage`/`Checkout`) and Take-Orders (`TakeOrdersPage`/
`OrderTaking`) screens -- both staff-facing, high-frequency-use workflows --
have never had a systematic design-quality pass since their C-14/C-19 Ant
Design rebuilds.

## Approach
Run the `ui-ux-pro-max` skill's audit checklist against `CashierPage`/
`Checkout` and `TakeOrdersPage`/`OrderTaking`. Given both are used rapidly
during service, prioritize touch target sizing, loading/feedback states on
async actions (checkout, order submission), and error clarity, alongside
standard accessibility, spacing/typography, and Ant Design token checks.
Fix concrete findings; log anything deliberately deferred with a reason.

## Acceptance criteria
- Cashier (Checkout) and Take-Orders (OrderTaking) screens audited against
  `ui-ux-pro-max` guidelines: accessibility, touch target sizing, async
  action feedback/loading states, spacing/typography consistency, Ant
  Design token usage.
- All concrete findings from the audit are fixed, or explicitly logged in
  this item's notes as an out-of-scope follow-up with a stated reason.
- The full frontend test suite passes with no regressions on both screens.
