# C-40: Auto-install PHP in deploy/setup.sh

`deploy/setup.sh` currently documents PHP 8.3+/Composer/PostgreSQL/Node as prerequisites the operator must install manually first (a deliberate C-9 decision: "this script does not touch system-level tooling... a restaurant's on-premise machine is set up once, not repeatedly"). This session hit the exact PATH gotcha `deploy/README.md` already documents from C-9 while debugging C-37's backend verification: winget installed PHP 8.3 on this dev machine, but the already-running shell session's PATH was stale, requiring a fresh terminal or an explicit full-path invocation. Add a PHP-presence check to `setup.sh`'s existing prerequisite check: if `php` is missing, install it via winget on Windows and resolve/use its full install path for the rest of that same script run, rather than immediately failing. Composer, Node/npm, and PostgreSQL remain manual prerequisites, unchanged.

## Acceptance criteria
- `deploy/setup.sh` detects a missing `php` on PATH and installs it via winget on Windows instead of immediately exiting with an error
- The script correctly locates and uses the newly-installed PHP for its own subsequent steps (composer install, artisan migrate) within the same run, without requiring the user to manually restart the script
- Composer, Node/npm, and PostgreSQL remain manual prerequisites, unchanged
- `deploy/README.md` updated to reflect PHP's new auto-install behavior, consistent with the existing Windows PATH / stale PM2 daemon documentation
- Script remains safe to re-run (idempotent) per its existing header comment
